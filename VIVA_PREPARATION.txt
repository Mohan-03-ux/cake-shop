Q1. What is your project about? Explain it briefly.

ANS: "BakedWithLove" is a full-stack Cake Shop Management System built
as my MCA final project. It is a web application where customers can:

  - Automating order collection and payment tracking
  - Giving the admin a dashboard to manage everything in one place

---------------------------------------------------------------

Q5. Why did you choose Flask over Django?

ANS: Django is a "batteries-included" heavy framework suitable for
large enterprise projects. Flask is a micro-framework that is:
  - Lightweight and easy to set up
  - Gives more flexibility and control
  - Perfect for a project of this size (small REST API + templating)
  - Easier to understand for a beginner MCA student
  - Requires fewer files and less configuration

---------------------------------------------------------------

Q6. Why SQLite and not MySQL or PostgreSQL?

ANS:
  - SQLite is file-based (database.db), so no separate server to install
  - It is built into Python's standard library (no extra installation)
  - It is sufficient for a single-user admin application
  - In production, this could be upgraded to MySQL or PostgreSQL

---------------------------------------------------------------

Q7. What is the role of Flask's Jinja2 templating?

ANS: Flask uses Jinja2 as its template engine. Instead of sending raw
HTML, Flask renders templates stored in the /templates folder and
injects dynamic Python data into them. For example:
  - render_template("admin.html") renders the admin dashboard
  - {{ v }} injects the cache-busting version number into all templates
  - This separates the HTML structure from the Python logic (MVC pattern)

Q9. How is the database initialized?

ANS: The function init_db() in app.py is called when the application
starts (inside the if __name__ == "__main__": block). It:
  1. Creates the admin table if it does not exist
  2. Creates the orders table if it does not exist
  3. Checks if default admin already exists — if NOT, it inserts one
     (username: admin@bakedwithlove.com, password hashed with Werkzeug)
  4. Runs ALTER TABLE migration to add new columns if missing

This pattern is called "lazy initialization" or "on-startup migration".

---------------------------------------------------------------

Q10. How do you prevent SQL Injection in your project?

ANS: I use parameterized queries (also called prepared statements) with
the ? placeholder syntax in Python's sqlite3 module. For example:

  cursor.execute("SELECT * FROM admin WHERE username=?", (data['username'],))

  Instead of:
  cursor.execute("SELECT * FROM admin WHERE username='" + username + "'")

The second way is DANGEROUS because a hacker could enter:
  username = ' OR '1'='1  → this would return all users!

Parameterized queries prevent this by treating user input as DATA only,
never as SQL code.

SECTION 4 — BACKEND / FLASK API QUESTIONS

Q11. What is a REST API? How have you implemented it?

ANS: REST (Representational State Transfer) is an architectural style
for building web APIs using standard HTTP methods:
  - GET    → Read/fetch data
  - POST   → Create new data
  - PUT    → Update existing data
  - DELETE → Delete data

In my project, the REST API endpoints are:

  POST  /admin-login           → Authenticate admin
  POST  /admin-logout          → Destroy admin session
  GET   /check-session         → Check if admin is logged in
  POST  /place-order           → Customer places a new order
  GET   /get-orders            → Admin fetches all orders
  GET   /sales-report          → Admin gets revenue summary
  PUT   /verify-payment/<id>   → Admin verifies a payment
  DELETE /delete-order/<id>    → Admin deletes an order
  GET   /shop-status           → Get shop open/close status
  POST  /shop-status           → Set shop open/close status

---------------------------------------------------------------

Q12. How does admin login work? Explain the security.

ANS: The admin login flow:

  STEP 1: Admin enters username + password on the frontend
  STEP 2: JavaScript sends a POST request with JSON to /admin-login
  STEP 3: Flask fetches the admin record from DB by username
  STEP 4: check_password_hash() compares the entered password with
          the stored hashed password
  STEP 5: If correct → session['admin_logged_in'] = True is set
          If wrong   → returns 401 Unauthorized JSON response
  STEP 6: All protected routes check session.get('admin_logged_in')
          before allowing access

  SECURITY FEATURES:
  - Passwords are hashed with Werkzeug's generate_password_hash()
    (uses PBKDF2-SHA256 by default — industry standard)
  - Plain-text passwords are NEVER stored in the database
  - Session is server-side (Flask session with secret key)
  - SESSION_COOKIE_SAMESITE = 'Lax' prevents CSRF attacks
  - SESSION_COOKIE_HTTPONLY = True prevents JavaScript from reading cookies

---------------------------------------------------------------

Q13. What is password hashing? Why is it important?

ANS: Password hashing is a one-way encryption process. Instead of
storing the actual password ("BWL@admin2024"), we store a hash like:
  pbkdf2:sha256:260000$xyz$abcdef1234...

  - HASHING is one-way: you can NEVER reverse it to get the original
  - Even if the database is stolen, hackers cannot see passwords
  - Werkzeug uses PBKDF2 (Password-Based Key Derivation Function 2)
    with SHA-256 and 260,000 iterations — very secure
  - Each hash includes a random "salt" to prevent rainbow table attacks

---------------------------------------------------------------

Q14. What is a Flask session? How is it different from cookies?

ANS:
  - A SESSION is server-side storage. Flask stores session data on
    the server and only sends a session ID to the browser as a cookie.
  - The SECRET KEY (app.secret_key) is used to sign/encrypt the
    session cookie so it cannot be tampered with by the user.
  - Regular cookies store data on the client side (browser) and can
    be read/modified by the user.
  - Flask sessions are more secure because actual data stays on server.

In my project:
  session['admin_logged_in'] = True   → Set on successful login
  session.clear()                     → Called on logout

---------------------------------------------------------------

Q15. What is jsonify() in Flask?

ANS: jsonify() is a Flask helper function that converts a Python
dictionary into a proper JSON HTTP response with the correct
Content-Type: application/json header. For example:

  return jsonify({"success": True, "message": "Login successful"}), 200

The second argument (200, 201, 401, etc.) is the HTTP status code.
This is how the backend communicates results to the frontend JavaScript.

Q16. What is localStorage? How have you used it?

ANS: localStorage is a Web Storage API available in all modern browsers.
It allows you to store key-value pairs (as strings) that persist even
after the browser is closed (unlike sessionStorage which is cleared).

In my project, I use localStorage for:
  - CART_KEY ('cremeco_cart')  → Stores the shopping cart as JSON
  - 'bwl_admin_open'           → Stores shop open/close status (true/false)
  - 'bwl_sms_log'              → Stores the simulated SMS notification log
  - 'bwl_reviews'              → Stores customer feedback/reviews
  - 'bwl_orders'               → Stores placed order records

Usage:
  localStorage.setItem('key', JSON.stringify(data));   // Save
  JSON.parse(localStorage.getItem('key'));              // Read
  localStorage.removeItem('key');                      // Delete

Q17. Explain the Cart implementation in your project.

Q18. What is the Intersection Observer API? How did you use it?

ANS: The Intersection Observer API lets you detect when an HTML element
becomes visible in the browser viewport (screen). It is used for
scroll-triggered animations.

In my project (initScrollReveal function):
  1. An observer is created with a threshold of 0.12 (12% visible)
  2. All elements with class "reveal" or "reveal-stagger" are observed
  3. When they enter the viewport → class "visible" is added
  4. The CSS animates them (fade in, slide up)
  5. observer.unobserve(entry.target) stops watching after animation

This is more efficient than using a scroll event listener, because
IntersectionObserver does not fire on every pixel scroll.

Q19. What is UPI and how does the UPI payment work in your project?

ANS: UPI (Unified Payments Interface) is India's real-time payment

It allows instant bank-to-bank transfers using a UPI ID.

In my project, UPI payment is SIMULATED (no real transaction):

          upi://pay?pa=slnmohan78-1@oksbi&pn=BakedWithLove&am=580.00&cu=INR
  STEP 4: QR code is generated from this URI using the QRCode.js library
  STEP 5: Customer can also open GPay/PhonePe/Paytm via deep links
  STEP 6: After paying, customer clicks "I have Paid" → WhatsApp opens
          with full order summary + payment confirmation message
  STEP 7: Admin verifies payment on WhatsApp and updates order status

  UPI ID used: slnmohan78-1@oksbi

Q21. What security measures have you implemented?

ANS:
  1. PASSWORD HASHING → Admin passwords stored as PBKDF2-SHA256 hashes
  2. PARAMETERIZED QUERIES → Prevents SQL Injection attacks
  3. SESSION AUTHENTICATION → All admin APIs check session before responding
  4. SAMESITE COOKIE → Prevents Cross-Site Request Forgery (CSRF)
  5. HTTPONLY COOKIE → Prevents JavaScript from stealing session cookies
  6. SECRET KEY → Flask uses it to sign/encrypt session data
  7. INPUT VALIDATION → Backend checks for required fields before DB insert
  8. 401/403 RESPONSES → Proper HTTP error codes for unauthorized access

---------------------------------------------------------------

Q22. What is CSRF? How does SameSite cookie prevent it?

ANS: CSRF (Cross-Site Request Forgery) is an attack where a malicious
website tricks a logged-in user's browser into making unauthorized
requests to your site.

Example attack:
  - User logs in to admin panel (gets a session cookie)
  - User visits evil.com which has a hidden form that POSTs to /delete-order
  - The browser automatically sends the session cookie → order gets deleted!

SameSite=Lax prevents this: the browser will NOT send the session
cookie when the request comes from a different website (cross-site).
The cookie is only sent for same-site navigation requests.

In my project: app.config['SESSION_COOKIE_SAMESITE'] = 'Lax'

Q24. What is MVC architecture? Does your project follow it?

ANS: MVC stands for Model-View-Controller:
  - MODEL      → Data and business logic (database operations)
  - VIEW       → What the user sees (HTML templates, CSS)
  - CONTROLLER → Handles requests and connects Model to View (Flask routes)

My project partially follows MVC:
  - MODEL      → SQLite database + functions like get_db(), init_db()
  - VIEW       → HTML templates in /templates folder + CSS/JS files
  - CONTROLLER → Flask route functions in app.py (place_order, get_orders etc.)

Flask is not a strict MVC framework, but its structure naturally maps
to this pattern.

---------------------------------------------------------------

Q25. What is an API? What is the difference between GET and POST?

ANS: API (Application Programming Interface) is a set of rules that
allows two systems to communicate. In web development, a REST API
allows the frontend (browser) to request data from the backend (server).

  GET  → Used to RETRIEVE data (read-only)
         No request body; data passed in URL
         Example: GET /get-orders

  POST → Used to SEND/CREATE data
         Data sent in the request body (JSON in my project)
         Example: POST /admin-login with {"username":"...", "password":"..."}

  PUT  → Update an existing resource
         Example: PUT /verify-payment/5

  DELETE → Remove a resource
           Example: DELETE /delete-order/3

---------------------------------------------------------------

Q26. What is JSON? Where is it used in your project?

ANS: JSON (JavaScript Object Notation) is a lightweight data format
used to exchange data between systems. It uses key-value pairs.

Example:
  {"success": true, "message": "Login successful", "order_id": 42}

In my project, JSON is used for:
  1. All REST API request and response bodies (Flask <-> JavaScript)
  2. localStorage values (cart, orders, reviews stored as JSON strings)
  3. shop_status.json file to persist shop open/close state
  4. The CAKES array in JavaScript (object array with cake data)

Python's flask.jsonify() and JavaScript's JSON.parse() / JSON.stringify()
are used to convert between JSON strings and objects.

Q31. Why is your payment gateway not real?

ANS: Implementing a real payment gateway (like Razorpay, Stripe, or
PayU) requires:
  - A registered business with GST
  - Bank account verification and KYC
  - Payment gateway API keys (requires approval)
  - HTTPS/SSL certificate (required for real payments)

For an MCA academic project, implementing a SIMULATED UPI gateway
with QR code generation, UPI deep links, and WhatsApp verification
demonstrates the full architecture and understanding of how real
payment systems work. In production, this would be replaced by
a Razorpay or Stripe integration with minimal code changes.

---------------------------------------------------------------

Q32. What happens if two customers place an order at the same time?

ANS: This is called a RACE CONDITION or CONCURRENCY issue.

In my project, since SQLite handles one write at a time (serialized
writes), data corruption is unlikely. However:
  - SQLite has limited support for concurrent writes
  - In a high-traffic production system, MySQL + proper transactions
    (BEGIN TRANSACTION, COMMIT, ROLLBACK) would be used
  - Order IDs are generated with a random suffix (BWL-20240801-A3K7)
    to minimize collision chances

Q34. What is the difference between localStorage and sessionStorage?

ANS:
  localStorage:
  - Data persists until manually cleared (even after browser close)
  - Shared across all tabs of the same origin
  - Used for: cart, theme, orders, reviews (should persist long-term)

  sessionStorage:
  - Data is cleared when the TAB is closed
  - Not shared between tabs
  - Used for: temporary single-session data

  In my project, I primarily use localStorage so the cart is not
  lost when the customer switches between pages or closes and reopens.

---------------------------------------------------------------

Q35. What is CORS? Is it relevant to your project?

ANS: CORS (Cross-Origin Resource Sharing) is a browser security
mechanism that blocks web pages from making requests to a different
domain than the one that served the web page.

In my project:
  - Frontend (HTML) and Backend (Flask) run on the SAME origin
    (http://127.0.0.1:8080), so CORS is NOT an issue.
  - If in future the frontend was hosted on Netlify and the backend
    on a different server, I would need to add Flask-CORS:
    from flask_cors import CORS
    CORS(app)
